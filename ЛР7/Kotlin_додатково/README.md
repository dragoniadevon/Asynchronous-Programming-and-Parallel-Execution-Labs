# Додаткова частина: Kotlin і корутини

Ця частина необов’язкова. Вона повторює сценарій Java і допомагає пов’язати практику з лекцією. Можна здати лише основну частину на Java.

## Завдання

У `src/main/kotlin/Main.kt` допишіть чотири `launch(Dispatchers.Default)` у позначеному `coroutineScope`. Викличте в них `task` з параметрами, зазначеними в TODO. Більше змінювати не потрібно.

Звичайна помилка дочірньої корутини скасовує область та її інших дітей. `delay` реагує на скасування, а цикл «рейтингу» навмисно цього не робить. Область чекає виходу всіх своїх дітей, тому після помилки через приблизно 100 мс повернення з області зазвичай буде лише після завершення «рейтингу», приблизно через 600 мс. Часи орієнтовні. Задачі запускаються конкурентно, порядок їх фактичного старту та рядків виводу не гарантований.

Після виконання порівняйте з Java:

1. Хто ініціює скасування сусідніх задач після помилки?
2. Чому `coroutineScope` виходить пізніше за момент помилки?
3. Чому не можна просто поглинути `CancellationException`?

Очікуваний результат: помилка ціни виведена, `cleaned=true` у всіх чотирьох, `sawCancellation=true` у двох задач із `delay`, а «рейтинг» завершується без перевірки скасування. Під дуже великим навантаженням запуск може порушити приблизні часові орієнтири; повторіть експеримент і поясніть спостереження.

## Запуск

Потрібні JDK 17, Gradle та доступ до Maven Central для першого завантаження залежностей. Відкрийте цю папку як Gradle-проєкт в IntelliJ IDEA і запустіть `MainKt`, або в терміналі з цієї папки виконайте:

```bash
gradle run
```

Версії Kotlin і `kotlinx.coroutines` зазначено в `build.gradle.kts`. Це окремий приклад: Java-файл не потрібно перекладати рядок за рядком.
